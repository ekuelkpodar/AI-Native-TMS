# Deploying the AI-Native TMS demo

The repo ships a single-service Docker image: the FastAPI backend serves the
built Vite SPA (with SPA fallback), so the whole product — landing page at `/`,
app behind login — runs as one web service with same-origin `/api/v1`.

## Option A — Render (recommended, free, ~5 minutes)

1. Sign up at https://render.com (email or GitHub — no credit card for free tier).
2. Dashboard → **New** → **Blueprint** → select `ekuelkpodar/AI-Native-TMS` → **Apply**.
3. Render reads `render.yaml`, builds the Docker image, and gives you a public URL
   like `https://ai-native-tms-demo.onrender.com`.

Demo login: `admin@demo.tms` / `Demo1234!` (seeded automatically on first boot).

Notes:

- Free-tier services sleep after ~15 min idle; the first request wakes them (~30s).
- The container filesystem is ephemeral — the SQLite demo DB resets on
  redeploy/restart, and `seed.py` rebuilds fresh demo data automatically.
- A random `JWT_SECRET` is generated by the Blueprint; override it in
  Render → Environment for anything beyond a demo.

## Option B — Docker (any host)

```bash
docker build -t ai-native-tms .
docker run -p 8000:8000 ai-native-tms
# → http://localhost:8000
```

## Option C — docker-compose (local, multi-service)

`docker-compose.yml` defines `api` (port 8000) + `web` (nginx, port 8080, proxies
`/api` to the API). **Unverified** — Docker was not installed on the build VM.

## Switching the demo to Postgres

Set `DATABASE_URL` to a Postgres URL (Render: add a Postgres addon and link it).
No code changes needed — the same SQLAlchemy models run on both.
